# 収益化アイディアメモ（未実装・検討中）

作成日: 2026-09-21
ステータス: **アイディア段階。実装はしていない。**

## 方向性

人数・イベント頻度でプランを分けるのではなく、**クレジット制**にする。

- 新規登録で **無料50クレジット** を付与
- イベント1回の作成につき **10クレジット消費**（人数の大小は問わない。8vs8でも50vs50でも同じ10クレジット）
- クレジットが尽きたら課金導線へ
- **人数上限・頻度制限は設けない**（クレジットのみで管理するため不要という結論）

## 不正防止（複数アカウントでの無料枠使い回し対策）

課題: メールアドレスは無限に作れるため、メール単位で無料枠を管理すると再登録され放題になる。

対策の方向性:
- **一意性の担保を「メール」ではなく「電話番号」に置く**
- 登録時に電話番号をSMSワンタイムコードで認証（Supabase Phone Auth / Twilio Verify等）
- 同一電話番号への無料クレジット再付与を禁止
- 余力があれば：電話番号の種別判定（Twilio Lookup等）でVOIP/050番号を弾き、携帯番号のみ許可
- 同一IPからの登録に軽いレート制限
- 前提として「完全に不正をゼロにする」のではなく「割に合わない手間にする」ことがゴール

メールはログイン手段・通知先としては残すが、無料枠判定のキーにはしない。

## 課金方法の検討

### 選択肢A: Stripe等のオンライン決済（クレジットカード）
- 実装自体は容易（Stripe Checkoutなら短期間で導入可）
- ただし日本の**特定商取引法に基づく表示**が必要になり、事業者の住所・電話番号等を**Webサイト上で公開**する義務が発生する
- 自宅住所を公開したくない場合は**バーチャルオフィス**（月1,000〜3,000円程度）の住所を使うのが一般的な対処法

### 選択肢B: 請求書＋銀行振込（手動）
- 導入コストがほぼゼロ（決済システム不要、今すぐ開始できる）
- 相手が事業者（主催者）同士のBtoB取引であるため、選択肢Aのような公開義務の必要性が相対的に低い（ただし最終的な要否はケースにより異なるため、規模が大きくなる前に専門家に確認するのが望ましい）
- デメリット: 入金確認・催促などの手間が手動で発生する

### 推奨の進め方
1. まずは選択肢B（請求書＋銀行振込）でスタートし、住所公開の論点を先送りする
2. 有料顧客が増えて手動運用が回らなくなってきたら、バーチャルオフィス住所を用意した上でStripe等のオンライン決済に移行する
