## 2. なぜ静的JSON50本にしないか

スクアドの恋愛統計は「離婚率」「初婚年齢」など**変わらない事実**だったので、50本を作って50日ループさせる方式が機能しました。

生成AIのニュースは**鮮度が命**です。8月に「GPT-5.6が出た」と投稿しても、10月にもう一度同じ内容が流れてきたら、フォロワーには「情報が古い発信者」に見えてしまいます。

**推奨：投稿の都度、Geminiに直近のニュースを調べさせて生成する方式。**
Migoronの花畑指数・お出かけ開運指数と同じアーキテクチャです。

- 朝枠：Geminiに「直近7日間の生成AI新サービス・新機能ニュースを1つ、出典付きで140字程度にまとめて」と指示
- 夜枠：Geminiに「直近の企業・行政・個人クリエイターの生成AI活用事例を1つ、140字程度にまとめて」と指示
- **Google検索連携（grounding）を使うのが必須。** Gemini単体だと学習データの古い情報や、存在しないニュースを生成するリスクがあるため
- 生成結果は`?dry=1`のようなプレビューモードで一度必ず目視確認してから本番投稿にする運用にしたほうがいい（ハルシネーション対策）
- 同じニュースを連投しないよう、直近14日分の投稿履歴をRedisに保存し、プロンプトに「以下は既出なので避けて」と渡す

**実装コストは上がりますが、「ニュース発信アカウント」として成立させるにはここは妥協できない部分です。**

## 4. 動的生成に切り替えた後のカテゴリ・テンプレート

Geminiへの指示文（プロンプト）のベースとして使ってください。

### 朝：サービス・技術ニュース
- 新モデル・新機能のリリース
- 価格改定・キャンペーン
- 大手プレイヤー（OpenAI/Google/Anthropic/Adobe等）の動き
- テンプレ：`[サービス名]が[内容]。\n\n[一言の考察・示唆]。\n#生成AI #[サービス名]`

### 夜：取り組み事例・レビュー
- 行政・自治体の導入事例
- 企業の活用事例
- 個人クリエイターの活用トレンド（一般論。Jake さん個人の実例は含めない）
- ツール・サービスのレビュー観点（「初日で判断しない」等の評価軸そのものを紹介する形。特定サービスを断定的に評価する場合は出典を明記）
- テンプレ：`[主体]が[取り組み内容]。\n\n[数字や特徴]。\n[一言の考察]。\n#生成AI #[分野]`

**共通ルール**
- 出典が明確でない情報は投稿しない（ハルシネーション対策）
- 数字を出す場合は出典元を把握しておく（聞かれたら答えられる状態にする）
- 特定企業・製品への評価は「良い/悪い」の断定より「こういう人には向く」という書き方にする

## 5. CTA設計（月・水・金の朝のみ）

- **火・木・土・日・そして月水金の夜は、CTAなし。**
- 月・水・金の朝だけ、本文の末尾に1行足す形でCTAを追加
- **スクアドAIチャットとSCADビューティー（scad-beauty.vercel.app）を交互に**表示

実装上の注意：CTAは特定のツイートIDに紐づくものではなく、**投稿する曜日で判定するロジック**にしてください（`getDay()`で月=1, 水=3, 金=5を判定）。交互表示はRedisに直近の表示先を1件保存し、次回はもう一方を出す形が確実です（Migoronの二重投稿防止と同じ考え方）。

CTA文言の例：
```
\n\n---\n生成AIを実際のアプリに落とし込んだ例として、婚活AI相談アプリ「スクアド」も動いています。\nhttps://[scadchatappのURL]
```
```
\n\n---\n生成AIの活用例として、AIパーソナルカラー診断アプリ「SCADビューティー」も動いています。\nhttps://scad-beauty.vercel.app/
```

## 6. 実装タスク（Migoronチャット向け）

1. まず立ち上げ用の実例20本を静的JSONとして配置し、朝夜cronで回す（動的生成が完成するまでの繋ぎ）
2. 並行してGemini+Google検索groundingでの動的生成を実装
   - プロンプトに「直近7日以内のニュースのみ」「出典URLを含める」を明記
   - `safeParseJson`等でハルシネーション時のフォールバック（静的JSON20本から1本選ぶ）を用意
3. CTAロジックを曜日判定＋交互表示で実装（第5章参照）
4. cronは2本（朝7:30=前日22:30 UTC、夜22:00=13:00 UTC）
5. 環境変数：`JAKE_AI_X_API_KEY` 等（既存の `X_*` や `SCAD_X_*` と衝突しないプレフィックスにする）
   - **注意**：@jake_images_ は既にInstagram用トークン（`JAKE_IMAGES_ACCESS_TOKEN`）が存在します。X用は別サービス（X API）なので変数名が衝突することはありませんが、紛らわしいので `JAKE_X_*` のように明確に分けること

## 7. 運用メモ

- 実例20本は**2〜3週間で使い切る想定**（1日1本ペースなら朝夜合わせて10日で1周）。動的生成の実装を急ぐこと
- ニュースが尽きた・薄い日は「無理に出さない」判断も必要（宮古島/石垣島の週替わりのような機械的ローテーションが効かないジャンルのため）
- 数字を伴う統計（自治体導入率など）は総務省調査などの更新頻度に合わせて年1回程度の見直しを想定
