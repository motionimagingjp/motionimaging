# @jake_images 生成AIトレンド発信 X自動投稿 引き継ぎ書

作成日：2026年8月25日
渡し先：Migoron SNS自動投稿システムの改修を相談しているチャット

---

## 1. やりたいこと

X **@jake_images** で、生成AIのトレンド・ニュース・取り組み事例を発信する。
投稿タイミングは **スクアドチャット（@scadchatapp）と同じ、朝7:30・夜22:00の1日2本**。

| 枠 | 時刻(JST) | 内容 |
|---|---|---|
| 朝 | 7:30 | サービス・技術ニュース（新モデル・新機能・価格改定など） |
| 夜 | 22:00 | 取り組み事例・レビュー（行政・企業・個人クリエイターの活用） |

**CTAは月・水・金の朝のみ**、スクアドAIチャットとSCADビューティー（scad-beauty.vercel.app）を**交互に**誘導。それ以外はCTAなし（純粋な情報発信・個人ブランディング用アカウント）。

---

## 2. 【重要】このアカウントだけアーキテクチャが違う

スクアドの恋愛統計・スクアド夜枠の婚活ノウハウは**不変の事実**だったので、静的JSONを50〜100本作って延々ループさせる方式で機能しました。

**このアカウントは違います。** 生成AIのニュースは鮮度が命で、静的JSONをループさせると数週間で「もう終わったニュース」を流すことになります。

**したがって実装方針を分けます：**

- **本番：Geminiに投稿の都度、直近ニュースをGoogle検索groundingで調べさせて生成する。** Migoronの花畑指数・お出かけ開運指数と同じアーキテクチャ（コード資産の流用が効く部分）
- **繋ぎ：立ち上げ用の実例20本（`jake_images_tweets_starter.json`）を静的JSONとして用意した。** 動的生成の実装が終わるまでの一時運用専用。1日1本ペースでも10日で1周するので、**2〜3週間以内に動的生成へ切り替えることを前提にすること**

---

## 3. 用意済みの素材

- `jake_images_tweets_starter.json` — 立ち上げ用の実例20本（朝用10本／夜用10本）。全件Web検索で出典確認済み（2026年8月25日時点）
- `jake_images_ai_trends_plan.md` — 企画の全体像（カテゴリ設計・動的生成のプロンプト方針・CTA設計の詳細）

### `jake_images_tweets_starter.json` のスキーマ

```json
{
  "meta": { "account": "...", "purpose": "...", "verified": "...", "slots": {...} },
  "items": [
    { "id": 1, "slot": "morning", "cat": "新モデル", "source": "...", "tweet": "投稿本文" }
  ]
}
```

- `slot` が `morning` / `night` の2値。朝夜で別々にRedisのカウンタ・キーを持たせること（スクアドの`sukuado_morning_idx`/`sukuado_night_idx`と同じ考え方）
- `source` は管理用（投稿には使わない）。日付が入っている情報が多いため、**この20本を使い切ったら内容ごと差し替える**（スクアドのように同じ50本を回し続ける想定ではない）
- 文字数（重み付き）は最大224、上限272に対して余裕あり。検証済み

## 4. 要決定事項（実装前に決めたい）

### 4-1. 動的生成のプロンプト設計

- 朝：「直近7日以内の生成AI新サービス・新機能・価格改定のニュースを1つ、出典URLを含めて140字程度の日本語でまとめて」
- 夜：「直近の生成AI活用事例（行政・企業・個人クリエイターいずれか）を1つ、出典URLを含めて140字程度の日本語でまとめて」
- **Google検索connector（grounding）を必ず有効にする。** Gemini単体だと存在しないニュースを生成するリスクがあるため
- 生成結果は`?dry=1`で一度必ず目視確認できるようにする（ハルシネーション対策。Migoronの`?dry=1`と同じ運用）
- 直近14日分の投稿履歴をRedisに保存し、プロンプトに「以下は既出なので避けて」と渡して重複を防ぐ

### 4-2. ハルシネーション時のフォールバック

Geminiの生成が失敗（JSON解析エラー・出典が取得できない等）した場合、**`jake_images_tweets_starter.json`から1本を選んで投稿する**フォールバックを入れる。Migoronの`safeParseJson`と同じ考え方（1つの失敗で投稿自体を止めない）。

### 4-3. CTAロジック

CTAは特定の投稿IDに紐づくものではなく、**投稿する曜日で判定する**。

- `getDay()`で月(1)・水(3)・金(5)の**朝枠のみ**CTAを付与
- スクアドAIチャットとSCADビューティーを**交互に**表示。Redisに直近どちらを出したかを1件保存し、次回はもう一方を出す（Migoronの二重投稿防止と同じキー設計）

CTA文言例：
```
\n\n---\n生成AIを実際のアプリに落とし込んだ例として、婚活AI相談アプリ「スクアド」も動いています。\nhttps://[scadchatappのURL]
```
```
\n\n---\n生成AIの活用例として、AIパーソナルカラー診断アプリ「SCADビューティー」も動いています。\nhttps://scad-beauty.vercel.app/
```

### 4-4. X APIトークン・アカウントの扱い

`@jake_images` は**X投稿用に新規でトークンを発行する**（Migoron・スクアドとは別）。
環境変数は `JAKE_X_*` のプレフィックスにすること。

**注意：** 既存の `JAKE_IMAGES_ACCESS_TOKEN`（Instagramの@jake_images_用）と紛らわしいので、変数名で必ず区別すること。
- Instagram：`JAKE_IMAGES_ACCESS_TOKEN`（既存・Migoronリポジトリ内）
- X：`JAKE_X_API_KEY` / `JAKE_X_API_SECRET` / `JAKE_X_ACCESS_TOKEN` / `JAKE_X_ACCESS_SECRET`（新規）

## 5. 実装タスク

1. **まず立ち上げ用**：`jake_images_tweets_starter.json` をリポジトリに配置し、朝夜cronで順番に投稿（スクアドと同じRedisカウンタ方式）
2. **並行して動的生成を実装**
   - Gemini + Google検索groundingで朝/夜それぞれのニュースを生成
   - `?dry=1`で生成結果を確認できるようにする
   - 生成失敗時は静的JSONへのフォールバック
   - 直近14日の投稿履歴チェックで重複防止
3. **CTAロジック**：曜日判定＋交互表示（4-3節）
4. **エンドポイント**：`/api/post-jake-ai-morning` と `/api/post-jake-ai-night` の2本
5. **Vercel Cron 2本登録**：`30 22 * * *`（朝7:30 JST）／`0 13 * * *`（夜22:00 JST）
   - ※ スクアドの夜cronと同時刻。別エンドポイント・別Xアカウントなので競合しない
6. `?key=` `?dry=1` `?force=1` `?report=1` を実装（Migoron・スクアドと同じ運用パターンに揃える）
7. 環境変数：`JAKE_X_API_KEY` / `JAKE_X_API_SECRET` / `JAKE_X_ACCESS_TOKEN` / `JAKE_X_ACCESS_SECRET`
8. X APIのプリペイド課金設定（`@jake_images`用に新規。スクアド・Migoronとは別残高）

## 6. 運用メモ

- **立ち上げ用の20本は2〜3週間で使い切る想定。** 動的生成の実装を後回しにしすぎないこと
- 動的生成が動き出したら、静的JSONは「フォールバック専用」として残す（削除しない）
- 数字を伴う統計（自治体導入率など）は総務省調査などの更新頻度に合わせて年1回程度、内容の古さを確認する
- ニュースが薄い日は「無理に出さない」判断も必要。Migoronの宮古島/石垣島のような機械的ローテーションが効かないジャンルであることを念頭に置く
- CTA先の2つ（スクアドAIチャット／SCADビューティー）は今後増える可能性がある。増えた場合は交互表示ではなくローテーション（Redisに配列で持たせる）に変更する

## 7. 補足：他プロジェクトとの違い

| | Migoron | スクアド（朝・夜） | @jake_images（本件） |
|---|---|---|---|
| コンテンツの性質 | 天気・暦（毎日変わる） | 不変の統計・実務ノウハウ | **ニュース（鮮度が命）** |
| 生成方式 | Gemini都度生成 | 静的JSON（50本ループ） | **Gemini都度生成が本命**（静的20本は繋ぎ） |
| grounding | Open-Meteo API | 不要（事前確定） | **Google検索必須**（ハルシネーション対策） |
| CTA | なし | 一部の投稿に付与 | **曜日判定＋2先を交互** |
