# ハウツーアプリPR動画制作 振り返り（ヨイナビ／沖縄居酒屋風）

作成日：2026年10月9日
対象：スクアドソロ（ヨイナビ）YouTube Shorts PR動画・沖縄居酒屋風バージョン制作
目的：アプリ紹介・ハウツー系動画を今後作る際に同じ手戻りを防ぐ

---

## 1. 起きたこと（時系列の要約）

1. 既存のスクリーンレコーディング素材をベースに「レトロアニメ風」「沖縄居酒屋風」などバリエーションを作る指示を、**色調エフェクト（eq/rgbashift等）で加工する意味**だと誤解して着手 → ユーザーから「エフェクトで直すという意味ではない、AIで動画自体を作り替えてほしい」と明確な訂正が入り、Higgsfieldのad-multiplier（Recreate）によるAI動画再生成に作り直し。**手戻り：フル2本分の無駄な生成**
2. AI再生成1回目：プロンプトに「izakaya」「入口付近」等の語を入れたら、屋内のはずが屋外の屋台シーンになった。原因は地名・外観を連想させる語（入口・屋根など）がプロンプトに含まれていたこと
3. 動画でしか確認せず進めた結果、「屋外になっている」「途中でフリーズする」「カラオケに切り替わらない」等の不具合をユーザーに都度発見される形になった → ユーザーから「静止画で先に見せてから進めて」と明確な指示
4. ffmpeg合成の実装バグ2件（`overlay`の`shortest=1`が映像全体を切り詰める／`-loop 1`画像の尺が主映像より長く余剰フレームができる）で、確認時に「途中で止まる」不具合が発生
5. 参考静止画の一部が、別の目的（別キャプション）で焼き込み済みのキャプション帯を含んだまま切り出されており、「色がおかしい（黒くハイライトされている）」とユーザーに指摘された
6. ユーザー自身が動画を編集し直したバージョンをアップロードし、それをベースに追加修正を依頼 → **その時点から「自分のビルド」ではなく「ユーザーが今持っているファイル」を正としてベースに切り替える必要があった**
7. 最終チェックで、常時字幕の1文字が文字化け（「遊べる」が「曾べる」と誤表示）、エンドカードのリンクが `scad-solo.vercel.com` と誤ったドメイン（正しくは `.vercel.app`）になっていた

---

## 2. 根本原因と教訓

### 2-1. 指示解釈のズレ（最大の手戻り要因）
- 「スタイルのシリーズを増やしたい」という曖昧な指示を、自分にとって実装しやすい方（既存素材への色調フィルター）に寄せて解釈してしまった。
- **教訓：** 「見た目を変える」「作り替える」等、実装方法が複数通り考えられる指示が来たら、着手前に「①既存素材にエフェクトをかける ②AIで映像そのものを再生成する」のように選択肢を明示して確認する。特にAI動画生成はクレジット消費が大きいため、方向性を外すと金銭的コストも時間的コストも大きい。

### 2-2. 屋内／屋外などAI生成特有の誤生成
- プロンプトの単語選び（「入口」「屋根」等）が意図せず外観を連想させ、モデルが屋外シーンを生成した。
- **教訓：** 場所の指定は文章だけでなく、**ロケーションの参照画像（generate_imageで屋内限定の静止画を先に作る）を渡す**方が確実。テキストだけで「fully indoor, no exterior, no sky visible」と強調しても、連想を誘発する単語が他にあれば負ける。

### 2-3. 動画を生成してすぐ確認せず進めてしまった
- 複数の不具合（屋外化、フリーズ、カラオケに切り替わらない）が、ユーザー側の視聴で初めて発覚した。
- **教訓：** AI動画は1本あたりのコスト・生成時間が大きいので、**生成直後に自分で最低限のフレーム確認（静止画抽出）をしてから次の工程に進む**。ネットワーク分離環境でも「1フレームだけ小さいJPEGでbase64往復させる」手法で確認可能（本プロジェクトで確立済み）。

### 2-4. ffmpeg合成の実装バグ
- `overlay=...:shortest=1` は「そのオーバーレイ入力が終わったら全体の出力も切り詰める」という挙動になり、単にオーバーレイを消すだけのつもりが動画全体を短くしてしまった。→ `eof_action=pass:shortest=0` を使うのが正解。
- `-loop 1` で読み込む静止画オーバーレイは、`-t` で主映像と**全く同じ尺**を明示的に指定しないと、余剰の静止フレームがパディングされて動画末尾が伸びる。
- **教訓：** 合成前に小規模なテストレンダーで尺と繋がりを確認する。本番サイズでいきなり合成しない。

### 2-5. 参考静止画の切り出しミス
- 別工程で焼き込んだキャプション帯が残ったままのフレームを参考画像として使い、「色がおかしい」という誤解を生んだ。
- **教訓：** 参考静止画を切り出すときは、その時点までに焼き込まれている他の要素（キャプション帯・オーバーレイ等）を把握した上で、それらを避けた範囲でクロップする。

### 2-6. 「今どのファイルが正か」の取り違えリスク
- ユーザーが自分で編集したファイルをアップロードした後も、こちらが過去に自分でビルドした版をベースにしたまま進めそうになった。
- **教訓：** ユーザーが「これをベースにして」と言ったら、**その時点以降は必ずそのファイルパスを正として扱う**。自分の過去のビルドに戻って作業を続けない。迷ったら最初に該当ファイルの長さ・内容をffprobe／フレーム確認で把握してから着手する。

### 2-7. 文字化け・リンク誤り（今回最重要／恒久ルール化）
- 常時字幕の1文字だけが別の文字（曾）に化けていた。原因は特定できていないが、テキスト焼き込みの過程で文字コードや編集ミスが混入したと見られる。
- エンドカードのリンクが `scad-solo.vercel.com`（誤）になっており、正しい本番ドメイン `scad-solo.vercel.app` と異なっていた。
- **ユーザーからの明確なルール（必須・今後常に適用）：**
  > 「QRとリンクは間違ってはいけないから毎回設定時に確認して、動画生成後に必ずみてください。これはルール」
  - **リンク・QRコードを動画に入れる設定をする際は、入力前に正しいURLを一次情報（CLAUDE.md・Vercelダッシュボード等）で確認する。**
  - **動画生成・合成が完了した後は、必ずリンク／QR表示箇所のフレームを実際に抽出して目視確認する。** 「たぶん合っているはず」で済ませない。
  - 文字入りキャプション全般も、生成・合成後に全セグメントを一度フレーム確認してから納品する。

## 3. 次回からのチェックリスト（ハウツーアプリ動画制作用）

- [ ] 指示が曖昧な場合、着手前に実装方針の選択肢を提示して確認する（特にAI動画生成 vs エフェクト加工のような、コストが大きく異なる分岐）
- [ ] ロケーション・外観など誤生成されやすい要素は、テキストだけでなく参照画像を用意する
- [ ] AI動画生成後は、本編に進む前に静止画（最低数フレーム）で内容確認してから次の工程に進む
- [ ] ffmpeg合成は本番尺でいきなり作らず、小規模テストで尺・繋ぎを確認してから本番適用する
- [ ] 参考静止画を切り出す際は、その時点で焼き込み済みの他要素（キャプション帯等）を避けてクロップする
- [ ] ユーザーが自分で編集したファイルを渡してきたら、以降はそのファイルを正としてベースに切り替える（自分の旧ビルドに戻らない）
- [ ] **リンク・QRは設定前に正しいURLを一次情報で確認し、動画生成・合成後は必ずフレームを抽出して目視確認する（恒久ルール）**
- [ ] 常時字幕を入れる場合は、全セグメントのテキストを生成後に一通り目視確認する（文字化け・誤字のチェック）
- [ ] AI生成映像は手・指の形が不自然になりやすい既知の弱点があるため、人物が物を持つ・操作するカットは生成後に手の形・向きも確認する

## 4. 技術メモ（再利用可能な手法）

- **ネットワーク分離環境でのAI動画プレビュー：** Higgsfieldのサンドボックス（`sandbox_exec`）内で1フレームだけ小さいJPEG（幅120〜160px、q:v 20〜28程度）に縮小し、`base64 -w0`で出力 → ローカルにテキストとして保存 → `tr -d '\n' | base64 -d`で復元（改行除去が必須、しないと破損する）。1回のsandbox_exec呼び出しにつき1フレームのみ（stdout切り詰め対策）。
- **ffmpeg overlayの罠：** `shortest=1`は出力全体を切り詰める。オーバーレイを特定区間だけ表示したいだけなら`eof_action=pass:shortest=0`を使う。
- **`-loop 1`画像オーバーレイ：** 主映像と全く同じ`-t`を明示指定しないと末尾に余剰フレームが入る。
- **文字化け・誤字・誤リンクの修正を、元ファイルの編集権限がない（ユーザー編集済みの焼き込み済み動画）状態で行う場合：** 該当テキスト領域をクロップ→`boxblur`で元の文字を潰す→同位置に正しいテキストを`drawtext`で重ねる、という手法で、背景のテクスチャ（木目など）を保ったまま自然に修正できる。単色の黒塗りボックスは背景が暗い場合のみ違和感なく使える。
