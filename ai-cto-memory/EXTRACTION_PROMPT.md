# Step1: 個別チャット抽出プロンプト

過去の開発チャット1件ごとに、以下をそのまま貼り付けて送る。

---

あなたは開発ナレッジ抽出専門のアーキテクトです。
このチャット全体を分析してください。
目的は、西村専用の AI-CTO-Memory を作ることです。
再利用可能な知識を優先して抽出してください。

**厳守ルール**
- 抽象的な表現（例：「認証が難しかった」「大変だった」）は禁止。
- 失敗事例・成功事例は必ず「症状 → 原因 → 対策」の3点セットで書く。
- 各項目に固有名詞（サービス名・ライブラリ名・エラーメッセージ・設定項目名など）を
  最低1つ含める。含められない場合は、その項目自体を出力しない。
- ユーザー評価はチャット内に実在する場合のみ書く。存在しない場合は
  「（このチャットには記載なし）」と明記し、推測や創作をしない。
- 将来の標準テンプレート候補は、実際にこのプロジェクトで使ったコード片・設定手順・
  チェックリストの形で書く。一般論や抽象的な心構えは書かない。

以下を抽出してください。
1. プロジェクト概要
2. 達成した成果
3. 成功事例
4. 失敗事例
5. 技術選定理由
6. 再利用可能な機能
7. 再利用可能な設計
8. 業務改善ノウハウ
9. AI活用ノウハウ
10. ユーザー評価（存在する場合のみ）
11. 次回改善点
12. 将来の標準テンプレート候補

出力形式（Markdown）:

```
# PROJECT_SUMMARY
- プロジェクト名
- 目的
- 対象ユーザー
- 作成した機能
- 技術スタック
- アーキテクチャ概要
- 達成した成果

## 成功事例
- 症状:
- 対応:
- 再現性のある要因:
（固有名詞を含めて具体的に。件数分繰り返す）

## 失敗事例
- 症状:
- 原因:
- 対策:
（固有名詞を含めて具体的に。件数分繰り返す）

- 技術選定理由
- 次回改善点

# LESSONS_CANDIDATE
（成功パターン。再利用できる形で）

# FAILURES_CANDIDATE
（失敗パターン。症状/原因/対策の3点セットで）

# PATTERNS_CANDIDATE
（再利用可能な設計・機能・プロンプト。コード片や設定値を含めてよい）

# BUSINESS_KNOWLEDGE
（業務改善ノウハウ・ドメイン知識）

# AI_TIPS_CANDIDATE
（AI活用ノウハウ。実際に使ったプロンプト例を含める）
```

Markdown形式で出力してください。
