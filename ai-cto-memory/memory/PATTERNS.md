## 再利用可能な設計

### P1. SNS自動投稿ボイラープレート
Vercel Cron + Next.js route.js + Upstash Redis + Gemini + （必要なら）Open-Meteo。
「独立cronエンドポイント」＋「slotパラメータによる共通ハンドラ」＋「Redis冪等性（成功後更新）」の3点セット。新規SNS自動化案件の出発点として複数プロジェクトで実際に流用された。
- 根拠: Migoron → スクアードX → jake_images

### P2. slotパラメータによる共通ハンドラ設計
`runXxx(request, slotName)`のように、投稿内容・Redisキーだけを設定オブジェクトで切り替え、ロジック本体は1本化する。新しい枠を追加する際、コアロジックの変更は数行で済む。
- 根拠: スクアードX（朝/夜/宣伝）

### P3. 標準デバッグインターフェース
`?key=` `?dry=1` `?force=1` `?report=1` の4点セット。認証コメントアウトという危険な手法を廃止し、安全にデバッグ・プレビュー・強制実行・状態確認ができる。
- 根拠: Migoron → jake_images

### P4. 動的生成＋静的フォールバックの二段構え
本番は「投稿の都度AIに検索させて生成」、実装完了までの繋ぎ・障害時のセーフティネットとして静的コンテンツを用意する。
- 根拠: jake_images, スクアード（DECODEの段階的フォールバック：個人実データ→セグメント統計→一般論）

### P5. フロントAPI試行→モックフォールバック
フロントが本番API（Gemini等）を`fetch()`で試行し、失敗時は既存モックへ自動フォールバックする構成。APIキー未設定・通信障害時でもアプリが壊れない。
- 根拠: SCAD Beauty

### P6. 環境変数のプレフィックス設計
`{プロジェクト名}_{サービス名}_{項目}`形式（例：`SCAD_X_API_KEY`、`JAKE_X_ACCESS_TOKEN`）。複数アカウント・複数プロジェクトが同一リポジトリに同居する場合の事故防止に有効。
- 根拠: スクアードX/jake_images/Migoron共存リポジトリ

### P7. X投稿成功後にThreadsへベストエフォートでクロスポスト
Threads投稿の失敗をX投稿の成否から分離する設計。
- 根拠: jake_images

### P8. 複数アドバイザー（人格）をオブジェクト1個にまとめて管理する設計
`name / emoji / color / tagline / greeting / quick / prompt`（または`systemPrompt`）を1オブジェクトにまとめ、配列/テーブルで複数人格を管理する。人格追加・調整がコード変更なしで完結する。
- 根拠: スクアード/DECODE（`advisors.ts`）, SCAD CHAT（3アドバイザー：共感型・行動派・経験者）

### P9. 「このアプリについて」ページの共通テンプレート
①開発者の顔・タグライン→②機能紹介→③データ取扱い（安心材料）→④姉妹アプリ導線→⑤連絡先、という構成をオブジェクト化（`APP_ABOUT`等）し、シリーズ全アプリで使い回す。姉妹アプリ一覧は`kind: current/external/soon`のような配列データで管理し表示分岐する。
- 根拠: SCAD Beauty（`APP_ABOUT`）, SCAD CHAT（同構成＋姉妹アプリ配列管理）

## 再利用可能な機能

- `weightedLength(text)`：X（Twitter）の重み付き文字数計算（CJK・絵文字=2、URL=23固定）。X投稿を扱う全プロジェクトで再利用。
- `safeParseJson(raw)`：AI出力の安全なJSON抽出（コードブロック除去＋正規表現抽出＋try/catch、失敗時はフォールバック値）。
- `interleaveByCategory(items)`：カテゴリ・タグが偏った配列を決定的（非乱数）ラウンドロビンで均等分散。
- `tweetWithRetry(client, text, attempts)`：重複403は再試行せず、それ以外は指数バックオフでリトライ。
- `callGemini(apiKey, prompt, maxTokens)`：thinkingBudget:0設定＋思考パート除外の抽出付きラッパー。
- Instagram/Meta Graph API向け`metaFetch` + `formatMetaError`：エラー詳細（code/subcode/fbtrace_id）を統一フォーマットで返す。
- Vision画像分類（選択肢固定＋JSON限定出力）：後続のテンプレート分岐に確実に接続できる。

## 再利用可能なプロンプト

### 構造化データ限定出力（JSON中間層）
```
以下の条件で[対象]のスコア・情報を算出してください。
必ず以下のJSON形式のみで返してください。マークダウン不要。
{"...": "..."}
```
完成文でなく「数値＋短文のJSON」に限定し、整形はコード側で行う。

### ニュース系コンテンツ生成（動的grounding）
```
直近7日以内の[ジャンル]のニュースを1つ、出典URLを含めて140字程度の日本語でまとめて。
既出（直近N日分）を避けること。該当なしの場合は topic:"NO_NEWS" を返すこと。
```
Google検索grounding必須。ハルシネーション対策として`?dry=1`等での投稿前プレビュー確認とセットで運用する。

### Vision画像分類（選択肢固定）
```
これは[被写体]の写真です。以下の選択肢から最も当てはまるものを1つだけ答えてください。
選択肢: A, B, C, other
```

### 統計情報の注意書き（ユーザー向けAIアドバイス）
```
これは一般的な傾向であり、目の前の相手が必ずそうとは限りません。
個人の実データがあればそちらを優先してください。
サンプル数が閾値未満の場合は統計に触れないでください。
```

### 段階的開示レスポンス設計
```
①短く共感・要点のみ回答
②深掘りの余地があれば一言提案
③ユーザーが望めば見出し限定（3つ以内）の詳細フォーマットを表示
```
最初から全情報を出さず、UIの「もっと見る」的な操作と組み合わせて情報量を制御する。
- 根拠: SCAD CHAT, スクアード/DECODE v2（分析レポートの折りたたみ表示）

### Markdown記号混入の二重対策
①プロンプトで「アスタリスクや見出し記号を使わない」と明示的に禁止し、②表示前に正規表現で強制除去する。指示だけでは崩れることがあるため両方を組み合わせる。
- 根拠: SCAD CHAT
