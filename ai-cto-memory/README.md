# AI-CTO-Memory

西村さんの過去アプリ開発（7件）から再利用可能な知識を抽出し、今後の開発でClaudeが
活用できる「個人CTOメモリ」を作るための作業場所。

## ディレクトリ構成

```
ai-cto-memory/
├── README.md                  ← このファイル（運用手順）
├── EXTRACTION_PROMPT.md       ← Step1: 個別チャットに送るプロンプト
├── INTEGRATION_PROMPT.md      ← Step3: 7件を統合するプロンプト
├── projects/                  ← Step2: 個別PROJECT_SUMMARYの原本置き場
│   └── (例) 監査支援アプリ.md
└── memory/                    ← Step4: 統合済みの最終成果物（CLAUDE.mdから読み込む）
    ├── LESSONS.md
    ├── FAILURES.md
    ├── PATTERNS.md
    ├── AI_TIPS.md
    └── BUSINESS_PATTERNS.md
```

## 運用手順

1. **個別抽出**: `EXTRACTION_PROMPT.md` の内容を、過去7つの開発チャットのうち
   まず1件に送る → 出力を確認 → 「良い例/悪い例」の基準（下記）を満たしているか確認。
   OKならプロンプトを固定し、残り6件にも同じものを送る。
2. **保存**: 各チャットの出力結果を `projects/<アプリ名>.md` として保存する。
   **機密情報チェック**: 実際のAPIキー、顧客の個人情報、契約金額などが含まれていないか
   保存前に必ず目視確認する（環境変数名や設計方針は問題ないが、実際の値は伏せる）。
3. **統合**: 7件揃ったら `INTEGRATION_PROMPT.md` を使い、全PROJECT_SUMMARYをまとめて
   共通パターンを抽出する。
4. **配置**: 統合結果を `memory/LESSONS.md` 等5ファイルに保存する。
   このファイル群はルートの `CLAUDE.md` から `@ai-cto-memory/memory/LESSONS.md` の形で
   読み込まれ、以後このリポジトリでのClaude Codeセッションに自動で反映される。
5. **再発防止（今後の新規開発時）**: 新しいアプリ開発が一段落したら、そのチャットの最後に
   以下を送るだけでメモリが育っていく。
   ```
   今日はこれで終了です。このチャットからPROJECT_SUMMARYを更新してください。
   また、LESSONS追加候補／FAILURES追加候補／PATTERNS追加候補を抽出してください。
   ```
   出力された追加候補は、`memory/`配下の該当ファイルに手動でマージする。

## 品質チェック基準（抽出結果の合否判定）

- 良い例: 「Supabase認証でハマった → 原因: Redirect URL未登録 → 対策: 初回セットアップ
  チェックリスト作成」のように、症状・原因・対策が固有名詞つきで具体的に書かれている。
- 悪い例: 「認証が難しかった」のような抽象的な一文で終わっている。
- 悪い例が混ざっていたら、該当項目だけそのチャットに聞き返して具体化させる。

## 注意（このリポジトリの範囲について）

`motionimaging`は7アプリのうち1つ（画像生成サイト）のリポジトリであり、他6アプリは
別リポジトリの可能性が高い。他リポジトリでもこのメモリを使いたい場合は、
`memory/`配下のファイルをそのリポジトリにコピーするか、該当リポジトリのCLAUDE.mdに
要点を転記すること。
