## 2. 最重要ルール(順番を変えない)

1. **絵コンテ(画像)で流れが決まるまで、動画は作らない**
2. 絵コンテと一緒に、**カットごとのカメラの動き**も見せてOKをもらう
3. 動画化の前に、**クレジットの見積もり**(1本あたり・合計)を見せてOKをもらう
4. OKが出てから動画化 → 組み立て → 自動チェック → 完成
- 画像は約1クレジット、動画(kling3_0 pro 5秒)は約8.75クレジット。直しは必ず画像の段階で。

## 3. 依頼者(Jake)の好み

- 説明は簡潔に。確認は作業の**前**に。コードは書かせない(自動化を優先)
- 結果は短い文と表・リンクで
- **短く・速く・テンポよく**:全体 約14〜15秒、素材は1.4〜1.5倍速でも成立する作り。人物カットは1.5〜2.5秒で切り替え
- 自分でも編集して仕上げる。**短く切りやすい良い素材**を渡す
- 曲はJake自作(保存済み、`PARTYCONNECT_VIDEO_RULES.md` の表)。BGMは基本Jakeが投稿時に入れる。入れるなら声より小さく
- 機能紹介が複数あるなら、**全部の主要機能を見せる**(例:受付とマッチの両方)

## 3.5 動画の種類ごとの「スピード」と「曲」(2026-10-07 Jakeより)

| 動画の種類 | スピード | 曲 |
|---|---|---|
| ハウツー・宣伝・紹介(SCADコネクトなど) | **速くてよい。素材は1.4〜1.5倍速**、全体 約14〜15秒、人物カットは1.5〜2.5秒で切り替え | Jake自作の曲を使う(基本は投稿時にJakeが入れる。入れる場合は声より小さく) |
| **MV(ミュージックビデオ)** | **スピードはそのまま(等倍)**。速めない。曲のテンポ・長さに映像を合わせる | **Jake自作の曲が主役**。映像を曲に合わせて作る(曲を先に確認する) |

- 迷ったら、まず「ハウツー系か、MVか」をJakeに確認する(確認は作業の前に)
- 曲は、保存済みの5曲(`PARTYCONNECT_VIDEO_RULES.md` の「保存済みのBGM」表。TWO / Cold Moon, 4AM / 1AM / Dice / Lost in the Code)から選ぶ。曲の長さ・雰囲気は未確認なので、使う前に確認する
- MVは曲の長さが動画の長さになる。5秒のカットを曲に合わせて並べる(カット数が増える分、クレジットの見積もりを先に出す)
- MVでも、絵コンテ → カメラワーク確認 → 見積もり → 動画化の順は同じ。カメラワークとエフェクトのルール(下の4)も守る

## 4. カメラワークとエフェクト(2026-10-06 追加。単調だと飽きられる)

- カットごとに動きを変える。隣り合うカットで同じ動きを続けない
- 動きの例:後ろから前(押し込み)/右から左/左から右/ドローン風の俯瞰・降下・旋回/引き/見上げ+ズームイン/小さな手持ち揺れ
- エフェクト(光のにじみ、きらめき、フラッシュ、切り替えの勢い)は必要なところだけ。QRや文字の邪魔をしない
- エフェクトは組み立て(ffmpeg)で入れる。追加クレジットはかからない
- 実績:押し込み・横移動・引き・見上げズームは効いた。**ドローン風の降下は弱く、ゆるい寄りに見えた**(俯瞰を強くしたいときは、絵コンテの段階で高い位置からの絵にして `start_image` にする)
- 最初の絵と最後の絵(`start_image` + `end_image`)を指定すると、引き→寄りが確実に出せる

## 5. 絵コンテ(画像)のチェックリスト

- `gpt_image_2`、`quality: high`、9:16、黒帯なし、スマホで撮った生活感
- 小物は全カット統一(例:ストラップは紺の無地、カードは白。スマホは白一色)
- スマホの向き:画面は本人側、カメラ側には白い背面とレンズ
- 背景の人は年代・髪を確認(30〜40代、白髪なし)。表紙にも映る
- 配置の筋が通っているか(お客様は受付台の手前、スタッフは内側)
- 場面の筋が通っているか(「終わった」のカットは受付が終わったあとの場面。会場の外に1人で立たない)
- 看板・紙に読める文字を入れない。実在のロゴ・QRを真似しない
- 人物は大きく(頭と肩で画面の高さの約45%)。文字は顔にかけない
- 演技は控えめ。体が揺れる動きは避け、笑顔のカットは「肩から下を動かさず、片手のサインだけ」
- **スマホ・タブレットの画面は、スマホサイズに合った表示にする**:QRやチェックは**画面いっぱい**(変な余白・灰色の帯・反射の筋を入れない)。画面の中身の色は、**元の画面と同じにそろえる**(例:チェックはタブレットと同じ「白地に緑の丸と白いチェック」。色を反転させない)
- **QRを読み取る場面**:タブレットにQR → お客様のスマホの画面にもQRが映る(画面は本人側、背面のカメラをタブレットに向ける)→ 読み取れたら、スマホとタブレットの両方がチェックに変わる。①(読み取り前)と②(読み取り後)でスマホの位置・角度をそろえる(②は①の画像を参照して作る)。QRは本物に見えない模様にする
- 絵コンテを見るときは、縮小画像を `sandbox_exec` の `image_paths` で確認する(中身を直接見られないことがある)

## 6. 動画化・組み立て・確認

- `kling3_0`、`mode: pro`、5秒、`sound: off`
- プリセット(IN THE DARK、Earth zoom in など)を勝手に提案されて作成が止まることがある → 提案されたpreset_idを `declined_preset_id` に入れて、同じ内容で再送
- 組み立ては `sandbox_exec`(ffmpeg)。sandboxは短時間で消えるので、ダウンロード〜書き出しを1スクリプトにして `background: true`
- 完成動画のアップロード先は、書き出し前に `media_upload` で取り、スクリプト最後で PUT → `media_confirm`
- 人物カットは `eq=brightness=0.03:gamma=1.07` で少し明るく
- 画面録画は、時刻・電波・録画マーク・操作バーを切り、余白なしで全画面。下に「※画面はデモデータです」
- 声は `qwen_audio_tts`(Hana)。言い方の指示は短く(長いと指示文まで読み上げる)
- 書き出し後に自動確認:文字起こし(faster-whisper)でセリフ、`cv2.QRCodeDetector` でQR、代表フレームで文字かぶり・黒帯・赤ボタンを見る
- エンドカードにQR必須。YouTube用とTikTok用でUTMを分ける

## 7. つまずき集

- Higgsfield(MCP)の接続が作業中に切れる → `sandbox_exec` のファイルが消える。つながり直したら、素材を公開URLから取り直してスクリプトを最初から
- 生成物はこの環境から直接ダウンロードできない(403)。sandbox内で取得する
- アップロードの署名URLを手で書き写すと400 → `media_upload` で取り直す
- `upload.higgsfield.ai` がネットワーク設定で許可されていないと403
- `media_upload_widget` は1ファイルずつ。ファイル名が変わって届くことがある
- ユーザーの手元の音・動画は、こちらでは聞けない/見られない前提で、自動チェックを使う

## 9. 新しい動画を作るときの最初の手順

1. この引き継ぎ書と、題材に合う個別ルール(SCADコネクトなら `PARTYCONNECT_VIDEO_RULES.md`)を読む
2. 誰に何を伝える動画か、主人公(Saki / Rio)、場面を決める → Jakeに短く確認
3. 絵コンテ(画像)+カメラワークの案を出す → 承認
4. クレジット見積もり → 承認
5. 動画化 → 組み立て → 自動チェック → 完成品のURL・表紙・投稿文を渡す
6. 新しく分かったことは、この引き継ぎ書に追記してコミットする(PRは頼まれたときだけ)
